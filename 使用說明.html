# iMac Solo 0.1.0 — 內建螢幕控制工具（實驗版）

**針對需求：iMac M1 + 使用者自述 macOS 27 + USB-C 轉 HDMI 外接螢幕。**
交付的是可在 Mac 本機建置的完整原始碼安裝包，不是已公證、已在實機通過驗證的二進位 App。

## 先看這一段

這個工具透過非公開的顯示器設定介面，嘗試讓內建顯示器退出 macOS 線上桌面。
**不是黑色桌布、不是黑色覆蓋視窗、不是降低亮度。**
不改外接螢幕的解析度或亮度，也不送出關閉所有螢幕的命令。

「顯示器離線」不等同於能證明面板電源軌完全斷電。請自行目視確認背光。
本包作者沒有 iMac M1／macOS 27 實機或 macOS SDK 建置環境，因此：

- 已做 Swift 語法解析、53 項純安全政策測試與安裝腳本語法檢查。
- **尚未完成 macOS SDK 型別檢查／編譯、iMac 實機切換、背光、功耗、喚醒與穩定性驗證。**
- 在你的 Mac 執行安裝時，才會用當地 Apple SDK 編譯 App；編譯失敗會停止，不會改顯示器。
- 非公開 API 可能失效、卡住或造成黑屏。安全監控是降低風險，不是絕對保證；先儲存工作。

## 安裝（不用購買授權）

1. 在 **那台 iMac** 下載並完整解壓縮 ZIP。不要只移出安裝檔。
2. 閱讀 `使用說明.html`，接好 HDMI，讓兩個螢幕都能正常顯示。
3. 雙擊 `安裝.command`。
4. 若 Apple 提示安裝 Command Line Tools，按 Apple 視窗的「安裝」，完成後再雙擊 `安裝.command`。
   不用下載完整 Xcode，也不用安裝 Homebrew。Apple 的工具安裝可能要求系統授權。
5. 安裝器先跑不會碰螢幕的安全測試，再編譯原生 App，安裝至：
   `~/Applications/iMac Solo.app`。
6. App 會顯示控制面板，右上方選單列也會出現螢幕圖示。**安裝及首次啟動均不會自動關屏。**

若下載檔案被 macOS 阻擋，先核對來源並閱讀程式，再透過「系統設定 → 隱私權與安全性」
中該檔案的「強制打開」（Open Anyway）單次允許。不要關閉 Gatekeeper 或 SIP。
若 `.command` 只被當成文字、或不保留可執行權限：開啟終端機，輸入 `/bin/bash `（結尾一格空白），
把 `安裝.command` 拖進終端機，再按 Return。這是執行你下載的本機檔，不是下載遠端腳本。

安裝器不使用 sudo、不下載第三方依賴、不修改系統安全設定。
僅當缺少 Apple Command Line Tools 時，會呼叫 Apple 官方安裝入口。
本機建立的 App 只有臨時簽章（ad-hoc），**不是 Apple Developer ID 簽章／公證**。

## 第一次使用

1. 先儲存文件，退出 BetterDisplay、Lunar 或其他會切換螢幕的工具，避免同時控制。
2. 在 macOS 顯示器設定中使用「延伸桌面」，不要使用鏡像；HDMI 設為主要顯示器可減少混淆。
3. 在 iMac Solo 選取要保留的 HDMI 螢幕，按「測試 20 秒：只用外接螢幕」。
4. 程式會把控制面板移到外接螢幕，先問「這個視窗確實顯示在你的 HDMI 螢幕上嗎？」。
   確認真的在實體外接螢幕，才開始測試；不要把虛擬螢幕或遠端桌面當作實體輸出。
5. 系統驗證內建顯示器離線後，請檢查：
   - HDMI 畫面能看、滑鼠能操作；
   - iMac 本體螢幕沒有可見背光，而不只是黑色畫面；
   - 游標和視窗不會跑到內建螢幕的桌面。
6. **20 秒內**按「確認：外接正常，內建螢幕沒有背光 → 保留」。
   未按會嘗試恢復，不會自動判定通過。

第一次不要拔線測試保護功能。先確定正常開關成功，才考慮測試其他情況。
確認面板需至少約 690×680 的可用邏輯桌面空間；若外接螢幕縮放後太小，程式會拒絕開始。

## 日常操作

- **關閉內建螢幕：**選單列 → 測試只用外接螢幕 → 確認。每次都有倒數保護。
- **恢復內建螢幕：**控制面板或選單列 → 恢復內建螢幕。
- **離開：**選單列 → 恢復並結束。關閉控制面板視窗不等於結束程式。
- **睡眠：**允許 Mac 和螢幕正常睡眠。喚醒後嘗試恢復內建螢幕，不會自行再把它關掉。
- **開機：**沒有登入自啟動，沒有永久停用設定。開機、FileVault 解鎖及登入畫面不在控制範圍。

本版刻意不提供「忽略安全限制」、「停用最後一台螢幕」、「永久跨重啟停用」及自動關屏。
沒有執行「保持喚醒」的無限命令，不會阻止正常閒置睡眠。

## 安全保護的範圍

介面與安全監控是兩個獨立程序；監控接管唯一的停用操作，避免多程序同時改設定。
沒有合格外接螢幕、無法唯一識別內建螢幕、使用鏡像或缺少控制介面時，拒絕停用。
已知虛擬螢幕名稱、虛擬 vendor/model 及空槽位會被排除，但軟體無法完美辨認所有轉接器；
所以仍需你在實體 HDMI 螢幕上確認。

監控會在倒數未確認、介面管線關閉、心跳超時、所選外接螢幕不再在線上時嘗試恢復。
一般睡眠期間暫停操作；喚醒時恢復。收到系統關機通知後停止發出顯示器設定，避免關機時競爭。
API 若卡在 WindowServer、硬體重新列舉、程序同時被強制終止、系統崩潰，則無法保證恢復。
關閉外接螢幕的電源但它仍向 Mac 回報連線時，也不保證能偵測到「看不見畫面」。

所有設定只以本次登入工作階段提交；不改 NVRAM、不安裝核心擴充、不關 SIP、不改永久螢幕設定。
macOS 仍可能自行記住視窗位置；恢復螢幕後，不承諾把所有視窗搬回原來位置。

## 救援

1. 等待倒數及恢復程序完成。外接畫面仍在時，可直接按「恢復內建螢幕」。
2. 重新接上原本的 USB-C／HDMI 外接螢幕。
3. 在 iMac 執行 `緊急恢復.command`。若安全監控仍在執行，會通知它恢復，避免兩個程序搶寫設定。
4. 若恢復失敗但系統還能操作，正常重新啟動。此工具不會在下次開機自動停用內建螢幕。
5. 系統完全無反應時，強制關機是最後手段，可能遺失未儲存工作。

救援不保證成功；程式不會自行強制關機、重新開機、關閉 SIP 或搜尋猜測的顯示器 ID。

## 診斷、隱私、移除

控制面板的「複製診斷資訊」包含 OS 版本、Mac 型號、顯示器名稱與狀態、vendor/model 和暫時 ID。
不包含使用者名稱、電腦名稱、硬體序號、截圖或檔案內容。診斷會寫入剪貼簿，不會上傳。
本機記錄保存在 `~/Library/Application Support/iMacSolo/`，上限約 512 KB。
恢復紀錄包含本次開機的識別碼，用來避免把先前開機的螢幕 ID 當成目前的 ID；不傳送至網路。
工具沒有分析追蹤、帳號登入、訂閱、背景更新或網路請求。

建置失敗時，請提供 `安裝記錄.log` 最後的錯誤行。執行異常時先恢復，再提供複製的診斷內容。
分享完整記錄前可自行檢查是否含本機檔案路徑。

移除：先「恢復並結束」，再執行 `移除.command`，或將 App 移到垃圾桶。
沒有系統服務／登入項目需要解除安裝。記錄資料夾可手動刪除。

## 給開發者

原始碼在 `Sources/`。安裝腳本完整列出建置指令。
`Tests/main.swift` 是平台無關的安全政策測試，能在 Linux 或 macOS 使用 Swift 執行。
自動化實機測試沒有執行，未提供假造的硬體通過紀錄。

CLI（enable-only 的救援與 read-only 診斷）：

```bash
"$HOME/Applications/iMac Solo.app/Contents/MacOS/iMacSolo" --diagnose
"$HOME/Applications/iMac Solo.app/Contents/MacOS/iMacSolo" --restore
```

非公開介面 `CGSGetDisplayList`、`CGSConfigureDisplayEnabled` 於執行時載入；
公開的 `CGBeginDisplayConfiguration`／`CGCompleteDisplayConfiguration(.forSession)` 用於設定交易。
只在本機使用者確認後，由 guardian 經新鮮列舉及安全檢查，發出一次停用要求。
開源實作的技術資訊列在 `docs/SOURCES.md`。這是獨立實作，未封裝 BetterDisplay 或其付費功能。
